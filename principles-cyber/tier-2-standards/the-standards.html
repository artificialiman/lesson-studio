§01 · The Laws

The Laws

The field's conservation laws — stated once, obeyed since. Each is given as a defender would cite it on the job, not as a paragraph to read through.

Law 1 · The CIA Triad
Every security control serves one or more of three properties: confidentiality (only the right people read it), integrity (unaltered since trusted), availability (reachable when needed). A control whose property you cannot name is a control you do not understand.
Law 2 · Kerckhoffs's Principle
A system must stay secure even when everything about its design is public — only the key is secret. Security that depends on a hidden method is already broken, because methods leak. ("No security through obscurity.")
Law 3 · Least Privilege
Every user, process, and service receives the minimum access its job requires and no more. Least privilege sets the blast radius of every breach before the breach occurs.
Law 4 · Complete Mediation
Every access to every object is checked, every time. No trusted shortcuts, no cached "already allowed." The request that skips the check is the request that breaches.
Law 5 · Fail-Safe Defaults
The default answer is deny. Access is granted deliberately, never inherited by accident. A system that fails should fail closed, not open.
Law 6 · Defense in Depth
No single control is trusted to hold. Controls are layered — preventive, detective, corrective — so that one failure is survivable and never total.
Law 7 · Assume Breach
Prevention fails eventually against a determined adversary. A program must invest in detection, response, and recovery, not prevention alone — losses are decided after the wall is crossed.
Law 8 · Zero Trust
Trust is never granted by network location. Every request is verified — identity, device, context — inside the perimeter as rigorously as outside it. Least privilege, applied to the network.
Law 9 · Separation of Duties
No single person or process holds end-to-end power over a critical action. Two keys, two parties — so that one compromised actor cannot complete the whole harm alone.
The laws, reduced
confidentiality + integrity + availability = what you protect least privilege + complete mediation = how you contain defense in depth + assume breach = how you survive failure Kerckhoffs + zero trust + separation = what you never assume

Reference Plate · Pillar I

CVSS — The Common Vulnerability Scoring System

The Measured-Scale Equivalent — a vulnerability's severity as a number on a fixed, public scale
Grounded in: FIRST.org (Forum of Incident Response and Security Teams), the body that publishes and versions the CVSS specification.

The pH scale gave chemistry a single number that ranked acidity on a fixed, published axis. CVSS does the same for vulnerabilities: a 0.0–10.0 score, computed from defined metrics, so two defenders anywhere agree on how severe a flaw is without arguing.

BandScoreWorking meaning
None0.0No impact
Low0.1–3.9Patch in routine cycle
Medium4.0–6.9Schedule deliberately
High7.0–8.9Prioritize
Critical9.0–10.0Emergency — patch now
Base score is built from metrics such as: Attack Vector (Network / Adjacent / Local / Physical) Attack Complexity (Low / High) Privileges Required(None / Low / High) User Interaction (None / Required) Impact to C, I, A (None / Low / High)

Why a number beats an adjective. "Serious" means different things to different teams; 9.8 does not. Like pH turning "sour" into a position on a line, CVSS turns "bad" into a rank that drives a patch queue — and the base metrics show why the number landed where it did, so a working defender reads the vector, not just the digit.

Reference Plate · Pillar II

ISO/IEC 27001

The Governing-Body Equivalent — security as a managed, audited, certifiable system
Grounded in: ISO (International Organization for Standardization) and IEC — ISO/IEC 27001, the international standard for an Information Security Management System (ISMS).

IUPAC did not test individual compounds — it governed the system by which elements are named and placed. ISO 27001 governs the system by which an organization manages security: not a checklist of controls, but a certifiable discipline of running, measuring, and improving them.

an ISMS = policies + people + processes + controls, managed as one certification = an external auditor confirms the system actually runs the engine = Plan → Do → Check → Act (continual improvement)

Why a system, not a checklist. A control list tells you what to install once; an ISMS tells you how to keep it working as the organization and the threats change. The difference is the difference between a reaction run once in a lab and an industrial process held at steady state — and industry, as the companion chemistry volume knows, is where the standard has to hold continuously, not just pass one exam.

§04 · Master Glossary

Master Glossary

Every defined term across the five volumes, gathered in one place — the note-making strategy the companion chemistry series is built on.

AAA — authentication, authorization, accounting.

Access control — deciding which users reach which resources.

APT — advanced persistent threat; a patient, resourced, usually state-linked adversary.

ARTEX — open-source LLM-driven autonomous pentest framework (Go); ships no model of its own.

Asymmetric encryption — public/private key pair; public locks, private unlocks.

Attack surface — every point an attacker could try, including the forgotten.

Authentication — proving who you are (know / have / are).

Authorization — deciding what you may do.

Availability — the CIA property of being reachable when needed.

Blast radius — how far a compromise spreads; set by least privilege.

Blue team — the defenders: detection, response, hardening.

Buffer overflow — input exceeding reserved memory, overwriting adjacent memory.

CIA triad — confidentiality, integrity, availability.

CVE — a named, catalogued specific vulnerability.

CVSS — 0–10 severity score for a vulnerability (FIRST.org).

CWE — a named type of weakness (the class a CVE belongs to).

Confidentiality — only authorized people can read it.

Credential stuffing — reusing leaked passwords across sites.

Defense in depth — layered controls so one failure is not total.

Digital signature — hash encrypted with a private key; proves authorship + integrity.

Hashing — one-way fixed-size fingerprint; serves integrity; no key.

IR — incident response; the prepare→detect→contain→eradicate→recover→learn cycle.

Integrity — data unaltered since trusted.

Kerberos — ticket-based domain authentication.

Kill chain — the seven ordered stages of an intrusion.

Lateral movement — spreading host to host by abusing trust.

Least privilege — minimum access for the job, no more.

MFA — two+ factors from different categories.

MITRE ATT&CK — catalogue of observed adversary techniques.

OAuth 2.0 — delegated authorization without sharing a password.

OIDC — identity layer atop OAuth 2.0.

OWASP Top Ten — most common web application risks.

Password spraying — one common password against many accounts.

Privilege escalation — gaining more access than granted (vertical / horizontal).

Red team — authorized offensive testers emulating a real adversary.

Reference monitor — always-invoked, tamper-proof, verifiable access checkpoint.

Risk — likelihood × impact.

SAML — browser single sign-on for enterprise federation.

SIEM — centralized log collection, correlation, and alerting.

SOC — security operations centre; the blue team's watch floor.

Symmetric encryption — one shared key, locks and unlocks.

Threat model — asset + adversary + attack surface + acceptable loss.

TLS — transport encryption securing data in transit.

Trojan / Virus / Worm — disguised / host-attached / self-propagating malicious code.

Zero trust — verify every request; never trust by location.
