§01 · The Shared Machine

The Shared Machine

Every other section in this book is downstream of one sentence. This is where that sentence lives.

The founding reduction
security = separation + proof separation = one user's things, kept apart from another's proof = a user, made to demonstrate they are who they claim identity = the currency of security

A computer owned by one person, locked in one room, used by no one else, needs no security — it needs a door. Security begins the moment that stops being true: the moment a machine is shared. Every breach in this three-book project is, underneath, a failure of separation or a failure of proof.

I. The founding facts — the constants underneath everything

YearEventWhat it minted
1961CTSS at MIT — first widely used time-sharingThe password, as a login mechanism
1965Multics design beginsAccess control, designed in, not bolted on
1971Creeper crosses ARPANETFirst self-moving code
1972Anderson Report (US Air Force)First formal call for deliberate security
1975Saltzer & Schroeder publishThe permanent design rulebook
the password did not arrive to stop hackers — there were none yet. It arrived because a shared machine had to tell two honest users apart. Security's first mechanism was built for bookkeeping and only later asked to hold a line against an enemy. Almost every weakness in this book is a mechanism built for one job, asked to do a second, harder one it was never designed for.

II. The gate — authentication, authorization

Before anything else about a user can be decided, the user clears this gate. It has two posts, and the single most common confusion in the field is treating them as one.

GATE → What is being decided about this user? Who are you? → Authentication (proving identity) What may you do? → Authorization (granting permission)
authentication is the border post; authorization is the map of which buildings your visa opens. Letting the wrong person in and letting the right person into the wrong room are different holes, patched in different places — confusing them is why systems get "fixed" at the wrong layer and breached anyway.

III. Least privilege — the one principle every later breach re-teaches

least privilege = every user, program, process gets exactly the minimum access its job requires — and not one permission more. blast radius = how far a compromise spreads = set by the loosest permission in reach

The attacker rarely breaks in as an administrator. They break in anywhere, and climb — and the climb is only possible because some account somewhere held more power than its job required.

every catastrophic breach in this project is least privilege, violated and then exploited. The founding decade named the cure in 1975. The field is still failing to take it.

The complete hierarchy, restated

THE SHARED MACHINE (security becomes necessary at all) ↓ SEPARATION + PROOF ↓ CIA TRIAD (the three properties every control serves) → Pillar I ↓ GATE → AUTHENTICATION / AUTHORIZATION ↓ (who are you?) ↓ (what may you do?) three factors → Pillar III reference monitor; least privilege ↓ SALTZER & SCHROEDER (the eight rules all of it obeys) → Pillar II

Everything after this section was already obeying this one sentence — a shared machine must separate users and prove identity — before it was ever formally shown. This is the beginning not because the field happened in this order, but because everything else was already secretly derived from it.

Reference Plate · Pillar I

The CIA Triad

The Periodic Table Equivalent — the classification every control is read against
Grounded in: NIST FIPS 199 (2004), "Standards for Security Categorization" — confidentiality, integrity, and availability defined by a public federal standard, not by this book's author.

Every element in the chemistry Periodic Table earned its place through an external, checkable authority — IUPAC, not the book's author. This plate holds itself to the same standard: the three properties below are the categories a US federal standard uses to classify every information system, verifiable in FIPS 199 itself.

CONFIDENTIALITY → Can only the right people read it? INTEGRITY → Is it unaltered since it was trusted? AVAILABILITY → Is it there when the right person needs it?
PropertyThe questionWhat breaks it
ConfidentialityWho can see this?Theft, eavesdropping, leaks
IntegrityHas this been changed?Tampering, forgery, corruption
AvailabilityIs this reachable?Deletion, overload, ransom

Where the Periodic Table sorts elements by shell-filling family, the triad sorts every control by which of three properties it serves. A password serves confidentiality; a checksum serves integrity; a backup serves availability. When you cannot say which of the three a control protects, you do not yet understand the control.

The trade no one escapes. The three are not independent — they trade against each other constantly. The most confidential file is the one no one can reach, which destroys availability. The most available system is the one with no locks, which destroys confidentiality. Security is not maximizing all three; it is choosing the balance a situation actually needs — the same way a reaction's conditions are chosen, not maximized.

§02 · Cryptography is Born

Cryptography is Born

The one section where the mechanism is pure mathematics, and the mathematics is the security. A careless human can undo everything else in these books. A sound cipher cannot be talked around.

For all of history before this decade, secret writing was a craft of tricks — swap this letter for that one, and pray the enemy never works out the pattern. In two years, 1976 to 1977, it became a science with public rules, and the craft never came back.

The gate — three routes
GATE → What do you need, and who already shares a secret with you? Hide contents, both sides share a key already → Symmetric Hide contents, the two share NO secret yet → Asymmetric Prove contents unaltered, hide nothing → Hashing

Like isotope, ion, and molecule, the three look related and do genuinely different work. Two hide; one does not hide at all and is still cryptography.

I. Symmetric — one shared key, both directions

plaintext --(key)--> ciphertext --(same key)--> plaintext symmetric = one secret key, used to lock AND unlock
FactValue
Landmark standardDES — adopted 1977, key only 56 bits
Modern replacementAES — 128 / 192 / 256-bit keys
StrengthFast; ideal for bulk data
WeaknessBoth sides must already share the key secretly
symmetric is a strongbox with one key both people must hold. Wonderfully secure, and useless until you answer the one question it cannot answer itself — how did you both get the key?

II. Asymmetric — the idea that changed everything (1976–77)

key pair: public key → shared with everyone; LOCKS or VERIFIES private key → kept secret forever; UNLOCKS or SIGNS anything locked with the public key opens ONLY with the private key
FactValue
Diffie–Hellman1976 — two strangers derive a shared key in the open
RSA1977 — first practical public-key encryption and signatures
WeaknessSlow; impractical for large data
asymmetric solves symmetric's fatal flaw and inherits a new one. Strangers can communicate with no prior meeting — but it is too slow for real traffic. So the two combine: asymmetric is used once, briefly, to deliver a fresh symmetric key, and the fast cipher carries the conversation. Every secure web connection you have made is this handoff.

III. Hashing — the route that hides nothing and is still cryptography

input of ANY size --(hash)--> fixed-size digest same input → same digest · any change → totally different digest the digest → cannot be reversed to the input hashing serves INTEGRITY, uses NO key — it is not encryption

A well-built system never stores your password. It stores the hash. On login it hashes what you typed and compares digests — so a thief who steals the file steals fingerprints, not passwords.

encryption is meant to be reversed by the right key; hashing is meant never to be reversed at all. If there is no key and no way back, it is a hash, not a cipher — the field's most common beginner error is calling them the same thing.

The complete hierarchy, restated

CONFIDENTIALITY + INTEGRITY (the CIA properties maths can buy) ↓ GATE → SYMMETRIC / ASYMMETRIC / HASHING └── combined: asymmetric delivers a key, symmetric carries traffic ↓ DIGITAL SIGNATURE = hash + private key = proof of authorship + proof of integrity

Before 1976, a cipher's security lived in a secret method that always eventually leaked. After 1977, the method was published, the key was the only secret, and the security was mathematics anyone could inspect and no one could talk around. The decade did not improve cryptography. It changed what kind of thing it was.

Reference Plate · Pillar II

Saltzer & Schroeder's Eight

The Electronegativity Equivalent — the derivation underneath, not just the label
Grounded in: Saltzer & Schroeder, "The Protection of Information in Computer Systems," Proceedings of the IEEE, 1975 — eight principles stated once and never since replaced.

Electronegativity explained WHY a bond resolves the way it does, not just that it does. These eight principles do the same job for secure design: they are the derivation underneath every claim in this book that one system resists misuse and another does not.

#PrinciplePlain statement
1Economy of mechanismKeep it simple — you can only verify what you understand
2Fail-safe defaultsDeny by default; grant deliberately, never by accident
3Complete mediationCheck every access, every time — no trusted shortcuts
4Open designNever depend on the design being secret
5Separation of privilegeRequire more than one condition to grant access
6Least privilegeGive each part only the access it needs
7Least common mechanismShare as little as possible between users
8Psychological acceptabilityIf it is too hard to use correctly, it will be bypassed

The one students disbelieve. "Open design" is the principle beginners reject and the one that matters most. A lock whose security depends on nobody knowing how it works is already broken, because design secrets always leak. A good lock stays secure when the attacker holds the blueprints and lacks only the key. This single principle is why real cryptography (Pillar's neighbour, §02) is published openly, and why "security through obscurity" is a warning, not a method.

Where chemistry's electronegativity gave a continuous number — 0.96, 2.23, a threshold at 1.7 — these eight give a checklist instead: crossed or not crossed, rule by rule. A different shape, the same job — explain why the earlier claim holds, not just assert it.

§03 · The First Self-Moving Code

The First Self-Moving Code

The first place in the field where the threat runs on its own after launch — which makes it, quietly, the true ancestor of Book III. Autonomy did not arrive with AI. It arrived in 1971, in one line of text on a screen.

The gate — how does the code spread?
GATE → How does the malicious code spread? Attaches to a host file, waits for a human to run it → Virus Copies itself across a network, no human needed → Worm Pretends to be something wanted, is run willingly → Trojan
TypeNeeds a host file?Needs a human?Spreads by
VirusYesYes — runs the fileInfected files, shared and opened
WormNoNoCopying itself over the network
TrojanNoYes — installs itDeception — looking desirable
the three differ on one axis only — how much the attacker still needs a human to do. The worm is the dangerous one precisely because it removed the human — the same removal that makes the agentic attacks of Book III dangerous, fifty years later.

I. Creeper and Reaper — first move, first countermove (1971)

Creeper (1971): copied itself across ARPANET — "I'M THE CREEPER: CATCH ME IF YOU CAN." Reaper (1971): written to chase Creeper down and delete it.
the field's first attack and its first defense were born the same year, built on the same mechanism, differing only in intent. This is the permanent shape of the subject: offense and defense are the same tools pointed opposite ways, and whoever automates faster sets the pace. Book III is this sentence, with AI as the thing automated.

II. The Morris worm — the day the threat stopped being theoretical (1988)

FactValue
DateNovember 2, 1988
Internet size then~60,000 computers
Machines infected~6,000 — roughly 10% of the whole internet
IntentNot destructive — meant to measure the internet's size
What went wrongA reinfection bug made it copy onto machines repeatedly
FirstsFirst CFAA felony conviction; first CERT created

The worm destroyed no data. It did something stranger: it made machines unavailable — the third leg of the triad — purely by copying itself too eagerly. A program meant only to count the internet nearly switched it off.

the Morris worm proved that autonomy is the risk, not malice. Its author meant no harm; it harmed ~10% of the internet anyway, because a small bug multiplied by automatic self-replication became a catastrophe no human could hand-stop. This is the decade's sharpest warning to Book III — an autonomous attacker need not be clever or cruel to be devastating. It need only be fast, self-copying, and a little bit wrong.

What it exploited — vulnerabilities, named for the first time

RouteWhat it wasStill exploited?
Weak passwordsGuessed from a built-in dictionaryYes — password spraying, Book III
Buffer overflowMore data than a program reserved room forYes — a whole vuln class
Trusted hostsMachines that trusted each other blindlyYes — lateral movement
the worm used no magic — it used weak passwords, an unchecked input size, and over-trusting hosts. Three failures of the Saltzer & Schroeder rules (Pillar II), specifically complete mediation and least privilege. The field's first real disaster was the field ignoring the design principles it had written down thirteen years earlier.

One worm, still moving

Not a hierarchy this time. A worm does not announce itself — it just keeps copying, quietly, whether or not anyone is watching. Start with everything this book has said the enemy is: a human defeating separation or faking proof. Take the human away. What is left still spreads, still climbs, still fills the disk — because the danger was never only the human's cleverness, it was the automation set in motion and then uncallable.

In 1988 that automation was six thousand machines and an accident. In Book III it is an AI agent given one goal and left to run. The decade that invented the password also invented the thing that would outrun the human defending it.

The Three Factors & MFA

The Activity Series Equivalent — a fixed ranking that predicts what displaces what
Grounded in: NIST SP 800-63, Digital Identity Guidelines — the three authenticator factor categories as defined by a public federal standard.

The Activity Series does not describe attraction; it predicts eviction — a higher-ranked element displaces a lower one from its compound, every time, by fixed rank. The factor model does the parallel job for identity: a stolen secret's usefulness is displaced the instant a second factor from a different category is required.

Something you KNOW → password, PIN (weakest alone) Something you HAVE → phone, token, card Something you ARE → fingerprint, face (cannot be changed once copied)
Attack shapeWhat it reusesDisplaced by
Brute forceGuesses against one accountA second factor
Password sprayingOne common password, many accountsA second factor
Credential stuffingPasswords leaked elsewhereA second factor

The ranking that ends the war. Every password attack is one attack — the reuse of a knowledge-factor secret the attacker should not hold — and every one dies against the same countermeasure, a factor the attacker does not hold. Just as Zinc displaces Copper purely by fixed positional rank, MFA displaces a stolen password purely because proof now requires a category the thief cannot reach. The multi-decade war over passwords ends in one rule: never let one factor be enough.

Everything the sections lean on, in one place. The periodic table of the founding decade: the values and definitions a defender should hold before the material starts, not hunt for inside it.

The constants — dates to know cold

YearEvent
1961CTSS — the password enters computing
1965Multics — access control designed in
1971Creeper & Reaper — first self-moving code and countermeasure
1972Anderson Report — first formal call for computer security
1975Saltzer & Schroeder — the eight principles
1976Diffie–Hellman key exchange
1977RSA; DES adopted
1988Morris worm; first CFAA conviction; first CERT

Glossary — every definition, gathered

Access control — the mechanism deciding which users may reach which resources on a shared system.

Asymmetric encryption — encryption with a linked public/private key pair; what the public key locks, only the private key opens. Solves key distribution between strangers; slow for bulk data.

Authentication — proving a user is who they claim, by one of three factors: know / have / are.

Authorization — deciding what an authenticated user may do.

Availability — the CIA property that a resource is reachable when needed.

Buffer overflow — a flaw where a program accepts more input than it reserved memory for, letting the excess overwrite adjacent memory; if the attacker controls the excess, they can control the program.

CERT — Computer Emergency Response Team; the first was created after the Morris worm (1988).

CIA triad — confidentiality, integrity, availability; the three properties every control serves.

Ciphertext / plaintext — the scrambled output of encryption / the readable original.

Collision resistance — the hashing property that two different inputs should never share a digest.

Confidentiality — the CIA property that only authorized people can read something.

Digest (hash) — the fixed-size, one-way fingerprint a hash function produces.

Digital signature — a document's hash encrypted with the signer's private key; proves authorship and integrity, verified with the public key.

Factor — one of three categories of identity evidence: knowledge, possession, inherence.

Hashing — a one-way function mapping any input to a fixed-size digest; serves integrity, uses no key, cannot be reversed. Not encryption.

Integrity — the CIA property that data is unaltered since it was trusted.

Least privilege — every user, program, and process gets only the minimum access its job requires; it sets the blast radius of any compromise.

Multi-factor authentication (MFA) — combining two or more factors from different categories, so stealing one is not enough.

Reference monitor — the always-invoked, tamper-proof, verifiable checkpoint every access request must pass.

Security through obscurity — relying on a design being secret; a warning, not a method, because design secrets always leak.

Symmetric encryption — encryption with one shared key for both locking and unlocking; fast, but both sides must already share the key.

Trojan / Virus / Worm — malicious code that is run willingly through disguise / that attaches to a host file and spreads when run / that copies itself across a network with no human action.
