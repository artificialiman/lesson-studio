§01 · What AI Actually Changes

What AI Actually Changes

The whole book turns on one subtraction. Books I and II assumed a human at the keyboard. Take the human away — what changes, and what pointedly does not?

The reduction
classical attack = human skill × human time × human patience AI attack = same techniques × machine speed × machine patience what changed = speed, scale, tirelessness, cost what did NOT = the vulnerabilities, the kill chain, the defenses

This difference — not a difference of kind — is the entire subject. An AI attacker does not know a vulnerability class that Book II did not list. It runs the same short list from §04 of Book II, but it never gets bored, never sleeps, never gives up on the three-hundredth target because the first two hundred were dull.

The gate — is this actually new?
GATE → Faced with an "AI attack," ask what is new: New vulnerability class? → Almost never New technique? → Rarely Same techniques, faster, cheaper, at larger scale? → Almost always — THIS is the change
DimensionHuman era (Book II)AI era (this book)
SpeedDays to weeks per targetMinutes — targeting to privileged access reported under 3 hours
ScaleA few targets at onceHundreds in parallel
PatienceFatigue, boredom, errorNone — it retries a failed call in seconds
CostSkilled operator timeReported as little as $145 in model fees per campaign
VulnerabilitiesUnchanged — the same OWASP/ATT&CK families
the Morris worm (Book I) already proved autonomy is the risk, not novelty. AI did not invent self-running attacks; it gave them judgment. The worm could only do the one thing it was written to do. An AI agent reads the result of each step and chooses the next — autonomy with a brain attached, which is exactly the leap §02 is about.

§02 · The Agentic Loop

The Agentic Loop

The new reaction mechanism. Physical chemistry asked how fast and by what pathway a reaction proceeds; this section asks the same of an attack that steers itself.

The reduction — the loop
OBSERVE → read the current state of the target PLAN → an LLM chooses the next step toward the goal ACT → run a tool (scanner, request, script) ADJUST → feed the result back; loop again the operator sets ONE goal; the loop runs with little further input

In classical terms, the human used to be the loop — look at a result, decide the next move, act, look again. The agentic framework automates that judgment. One operator sets an objective; cooperating agents handle planning, execution, and revision in a repeating cycle, often across thousands of actions in a session.

the loop is a catalyst, not a new reaction. A catalyst (Book-companion Physical Chemistry) does not change what reaction is possible — it lowers the energy to make it happen, so far more of it happens. The agentic loop does exactly this to attacks: the same intrusions were always possible; the loop drops the human effort each one costs to near zero, so vastly more of them happen.

Why speed alone breaks a classical assumption

Book II's defender advantage: attacker must complete every kill-chain step IN ORDER defender needs to win ONCE, at any step AI era pressure: the seven steps can run in seconds, not weeks → the defender's window to "win once" shrinks toward zero
machine speed attacks the time in the kill chain, not the chain itself. The stages are unchanged — recon, deliver, exploit, escalate, exfiltrate — but a defense built to notice an intrusion over days is a defense built for a clock the attacker no longer runs on. This is why detection and automated response (§05) matter more in this book than in any before it.

The honest limit — hallucination

The loop is not magic. Because an LLM drives it, it can misread success — in one reported campaign, agents announced cash-outs that never happened, reading a server's "success" response as proof of theft when no funds had moved. The defender's lesson is not comfort; it is that AI-driven attacks are noisy and error-prone in ways a careful human is not, and that noise is a detection signal.

§03 · ARTEX — A Case Study

ARTEX — A Case Study

A single framework made the abstractions of §01 and §02 concrete in 2026. It is studied here the way a toxicology text studies a poison — to recognize it and treat it, not to administer it.

The reduction — what ARTEX is
ARTEX = a harness, NOT a model harness = the agentic loop + security tools, in one framework the model = supplied externally — ARTEX ships none of its own so = ARTEX = (any LLM API) + (the loop) + (standard tools)

ARTEX is an open-source, LLM-driven autonomous penetration-testing framework written in Go. It was built, like many tools in this field, for legitimate security testing — letting authorized teams test systems they own. The same properties that make it useful to defenders drew criminal and state-linked actors, who repurposed it.

FactAs reported
TypeOpen-source, multi-agent, LLM-driven pentest framework (Go)
OriginPublished on GitHub July 2026 by a developer using the handle "Autumn-27"
ClosedMade unavailable / closed-source Oct 8, 2026 after abuse reports; forks, mirrors, and a paid "ARTEX PRO" persist
ModelShips none — connects to external LLMs; attacker instances mostly used Chinese-origin models (esp. the DeepSeek Flash family)
Exposure1,600+ publicly exposed consoles as of early Nov 2026 (one study: 2,557 hosted, 1,608 live)
the "harness, not a model" fact is the single most important line in this book. It means you cannot defend by banning one model — take any capable LLM, drop it into the harness, and the attack resumes. The threat is the loop plus the tooling, not any one brain you might block. This is why defense returns to the fundamentals of Books I and II and not to the AI itself.

The autonomy, made real

What distinguished ARTEX activity from classical intrusions was the removal of the operator mid-attack. In several documented campaigns, nobody prompted the agents again after the initial goal was set — the loop retried failed calls within seconds and chose its own next steps across thousands of actions. Reported campaigns reached from initial targeting to privileged access in under three hours, and ran against hundreds of organizations in parallel.

ARTEX is the Morris worm (Book I) with judgment. The worm spread blindly and brought down 10% of the internet by accident. ARTEX spreads with a planner reading each result — the same removal of the human, now with the ability to adapt. The founding decade's quietest warning, collected in full fifty years later.

A note on model safeguards

Public reporting records that, in some instances, operators hit refusals when they pointed the harness at certain Western models with stronger safety guardrails — and then switched to more permissive models to continue. The defender's reading is twofold: model-level safeguards are a real friction on misuse, and they are not a perimeter, because a model-agnostic harness simply routes around a model that says no. Defense cannot be outsourced to the model's conscience.

§04 · The Constant That Didn't Change

The Constant That Didn't Change

The keystone of the trilogy. In every reaction a chemist runs, something is conserved — mass, charge, energy. In every AI attack reported to date, something is conserved too: the vulnerabilities.

The conservation law
conserved = the weaknesses exploited = weak/exposed credentials, unauthenticated APIs, over-permissive access, misconfiguration, unpatched flaws not conserved = the speed, scale, and cost of exploiting them therefore = the cure is conserved too — it is Books I and II

Across the documented ARTEX campaigns, the agents did not find exotic new holes. They found hardcoded passwords, plaintext credential files, unauthenticated endpoints, secrets left in public code, and accounts with more privilege than their job required — the exact failures named in Book I's Saltzer & Schroeder plate and Book II's vulnerability-classes gate. One reported path ran from a secret exposed in public code to sensitive cloud data in five minutes. The hole was old. Only the clock was new.

if the vulnerabilities are conserved, the defenses are too. This is the most hopeful sentence in the book and the most demanding. Hopeful, because you already know what to do — it is in Books I and II. Demanding, because machine speed means the hygiene you were allowed to defer in the human era is now the difference between a blocked probe and a three-hour breach.

Why "basic hygiene" is the expert consensus

What the agent exploitedThe Book I / II principle it violated
Hardcoded / exposed credentialsNever embed secrets; least privilege
Unauthenticated APIsComplete mediation — check every access
Over-permissive accountsLeast privilege — blast radius
Insecure defaultsFail-safe defaults
Reused / sprayed passwordsMFA — never let one factor be enough
the field's leading responders converged on the same unglamorous verdict: defending against an AI attacker is, overwhelmingly, the hygiene you already owed. The machine does not pick a better lock. It checks every unlocked door on the street, in seconds, tirelessly — so the only door that stays safe is the one that was actually locked.

Reference Plate · Pillar II

Detection at Machine Speed

The Qualitative-Analysis Equivalent — identifying the agent by its signatures, not by guesswork
Grounded in: published detection guidance from Check Point Research ("Hacking on Autopilot," Nov 5, 2026), Sophos X-Ops, SentinelOne, and the FBI FLASH indicator table.

Compound chemistry's qualitative analysis identified an unknown salt by the tests it reacts to — add this reagent, read that result. Detecting an AI-driven intrusion is the same discipline: it leaves signatures, and a defender reads them rather than guessing.

Signature classWhat to watch for (defensive)
TempoMachine-paced bursts — many actions in seconds; failed calls retried within seconds with small variations
IdentityOne identity authenticating to many service principals; tokens requested across many cloud services in a short window
ArtifactsPaths and strings containing "artx"/"artex"; reported working directories; web-server processes spawning shells
Exfil channelsRepeated callbacks to request-logging services used as drop points

The honest caveat, kept in the plate. Authorized penetration testers also run ARTEX. Every signature above is a lead, not a verdict — the same way a single qualitative test narrows a salt but does not name it alone. And infrastructure rotates, so indicators are validated before they are blocked. The durable detection signal is not any one string; it is tempo — the one thing a human attacker cannot fake and an AI cannot hide, because machine speed is the whole point of using the machine.

§05 · Mitigations

Mitigations

The four instruments, pointed at this threat. Every control here is drawn from public advisories — and every one is a control Books I and II already taught. They are gathered, not invented.

The reduction — four fronts
REDUCE SURFACE → close the doors the agent scans for HARDEN IDENTITY → make stolen credentials dead ends PROTECT APPS → stop input and secrets from leaking DETECT + RESPOND→ win on tempo, since speed is the attack

I. Reduce external attack surface

ControlWhy it blunts an AI attacker
Inventory every internet-facing app (incl. partner portals, legacy, mobile backends)The agent scans the doors you forgot; you cannot defend an unknown door
Restrict cloud admin, management, and backup interfaces to trusted networksRemoves the high-value targets from public reach
Move apps behind zero-trust access where feasibleEvery request re-verified, not trusted by location

II. Harden identity and access

ControlWhy
Least privilege on multi-tenant app permissions and consent grantsCaps the blast radius of any one stolen identity
Phishing-resistant MFA; block legacy auth; smart lockoutKills spraying and stuffing at machine scale
Monitor credential additions and new service principalsCatches the agent granting itself persistence

III. Strengthen application protections

ControlWhy
Scan repos, images, and pipelines for embedded secrets; rotate promptlyCloses the "exposed secret → cloud data in minutes" path
Enforce server-side authorization on every request; limit response fieldsComplete mediation — defeats the unauthenticated-API family
Rate-limit and alert on unusual volume on high-impact APIsTurns the agent's speed into its own alarm

IV. Detect, respond, preserve

ControlWhy
Alert on machine-paced bursts and rapid cloud enumerationTempo is the signal the attacker cannot hide (Pillar II)
Automate first response for fast, privileged paths (disable principal, revoke tokens), confirm afterOnly machine-speed response can meet a machine-speed attack
Preserve sign-in, audit, and SIEM logs before containmentAccounting (Book II) — no logs, no investigation
front IV is the only one that is genuinely heavier than in the human era. Fronts I–III are the old hygiene, now non-negotiable. Front IV is new in degree: when the attack runs in seconds, a response that waits for a human to read an email is a response that arrives after the breach. Automated, pre-authorized containment is the one place the defender, too, must hand judgment to a machine.

The complete hierarchy, restated

WHAT CHANGED = speed, scale, cost (§01) ↓ THE AGENTIC LOOP = a catalyst on old reactions (§02) ↓ ARTEX = a harness, not a model — can't be banned away (§03) → Pillar I ↓ THE CONSTANT = the vulnerabilities are conserved (§04) ↓ THEREFORE the cure is conserved: Books I + II, now mandatory ↓ DETECT ON TEMPO (Pillar II) + AUTOMATE RESPONSE (§05) = the one front that is new in degree

Reference Plate · Pillar III

The Arms Race

Creeper & Reaper, Returned — attack and defense, the same tool, pointed opposite ways
Grounded in: Book I, §03 (Creeper & Reaper, 1971) — and the 2026 consensus that defenders are applying the same agentic AI to detection and response.

In 1971 the first self-moving attack (Creeper) and the first self-moving defense (Reaper) were born the same year, the same mechanism, differing only in intent. The AI era is that sentence at full scale: the same agentic loop that drives ARTEX also drives autonomous defense — triage, detection, and response agents that read and act at the attacker's tempo.

offense AI = the loop + tools, pointed at breaking in defense AI = the loop + tools, pointed at catching the break-in the difference = intent, authorization, and oversight — not capability who wins = whoever automates the fundamentals faster

The trilogy's last conservation law. The oldest pattern in the field (Book I) is the newest news in it (Book III): offense and defense have always been the same tools in opposite hands, and the edge goes to whoever automates first. What AI did not change is the thing to end on — the defender's job is still separation and proof, least privilege and complete mediation, detect and respond. The machine made all of it faster. It made none of it different. A worm, in 1988, spent one night proving the field's quietest warning was never quiet. An agent, in 2026, proved the field's oldest principles were never obsolete.

Glossary — every term, gathered

Agentic framework — software that lets an LLM pursue a goal through a repeating observe–plan–act–adjust loop, with little human input after the goal is set.

ARTEX — an open-source, LLM-driven autonomous penetration-testing framework (Go); built for authorized testing, repurposed for attacks; ships no model of its own.

ARTEX PRO — a reported paid variant persisting after the original was closed-sourced.

Agentic loop — observe, plan, act, adjust; the mechanism that replaces the human's moment-to-moment judgment.

Conservation law (of this book) — the observation that AI attacks exploit the same vulnerabilities as before; only speed, scale, and cost change.

FBI FLASH — a US law-enforcement threat advisory; FLASH-20261113-001 covers ARTEX.

Hallucination — an LLM reporting an outcome that did not occur; in attacks, a source of noise and a detection signal.

Harness, not a model — the principle that ARTEX is the loop plus tooling, with the model supplied externally; the reason it cannot be defended against by banning any one model.

Machine-paced burst — a volume and speed of actions only automation produces; the most durable detection signal.

Model-agnostic — able to use any LLM API interchangeably.

Supply-chain compromise — abusing a trusted vendor's access to reach its downstream customers (e.g. the reported ConnectWise case).

Zero trust — verify every request regardless of location; the network-layer form of least privilege (Book II).
